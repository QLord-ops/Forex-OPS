# OPS Disponent — инструкции для Claude Code

Диспетчерская система грузового автопарка Forex GmbH (Bovenden). Пользователь — диспетчер: управляет машинами, турами, Auftrag, BELADEN/ENTLADEN, ETA и пробками. Интерфейс и тексты для пользователя — **на русском**; немецкие отраслевые термины (Auftrag, Tourbemerkung, BELADEN, ENTLADEN, LDM, Termin) остаются как есть.

## Стек

- `apps/api` — Fastify 5, Prisma 6, Zod, TypeScript (ESM, NodeNext). Production: PostgreSQL (DigitalOcean `ops-disponent-prod`), локально и в тестах — SQLite (`prisma/sqlite/`).
- `apps/web` — React 18, Vite, Tailwind, MapLibre (ленивая загрузка), lucide-react.
- Тесты: Vitest (`apps/*/tests`), Playwright (`e2e/`). Node 22 (`.nvmrc`).

## Команды

```bash
npm install
npm run db:setup          # локальная SQLite + seed
npm run dev               # API :3001, web :5173
npm run lint && npm run typecheck && npm test && npm run build
npm run test:e2e
npm run webfleet:check -w @ops/api   # одна read-only проверка ключа Webfleet
```

Перед каждым коммитом — все четыре проверки зелёные. Новая логика сопровождается тестом в `apps/api/tests`.

## Где что лежит

- `apps/api/src/app.ts` — все маршруты; сервисы — `apps/api/src/services/*`.
- `services/webfleet.ts` — Webfleet: синхронизация, сопоставление машин, ошибки, привязки.
- `services/vehicle-clock.ts` — расчёт часов машины (ЕС 561/2006), `termin-planner.ts` — паузы в пути по тахографу Webfleet (общий движок ETA и Termin: отдых 11 ч, 9 ч при раннем Termin; вождение 9 ч в день, даже если Webfleet считает до 10 ч, — 10-й час (`setExtendedDay`) берётся, только если без него машина опоздает к Termin и удлинённые дни ещё есть, владелец 19.11; у каждой точки маршрута показывается остаток вождения на месте — `driveLeftSeconds`, `lib/driving-day.ts`); без тахографа — те же правила по расчётным часам (`vehicle-clock.ts`): пауза 45 мин после 4 ч 30 езды, отсчёт по GPS от последней стоянки ≥ 45 мин (`drivingSinceBreak`). Каждый ETA (Диспозиция, расписание, уведомления, хронология, Termin, предпросмотр тура с временем на точках — `forecastRoute`, сценарии, «Изменить тур» — `forecastQueue` в `replanning.ts`; тот же редактор открывается прямо в карточке машины и у ещё не начатого тура в очереди, в том числе в середине очереди: время считается после всего, что машина сделает до него, переход следующего тура перестраивается, текущий этап машины не трогается (владелец, 26.11), утренний статус) считается с паузами по тахографу, без него — по расчётным часам; ETA каждой открытой точки тура на главной — `EtaService.stopEtas` (`eta.ts`): продолжается от ETA точки, к которой машина едет, со стоянкой 60–120 мин на каждой точке до неё (страница показывает середину со знаком «≈», диапазон — в подсказке), а пока тур не начат — «по плану» от Termin первой точки; `eta-breaks.test.ts` проверяет все пути, `tours.ts` — туры, `operations.ts` — прибытие/стоянки, `termin-groups.ts` — общий Termin: выгрузка и загрузка в одном месте (соседние точки ≤ 300 м, та же фирма или улица + индекс) идут под одним Termin, он хранится на первой точке места. Склад Abteilung («vorladen», «Lager», «divers») берёт только адрес, напечатанный в самом блоке Abteilung: адрес перевозчика (`carrierAddress` от модели и своя база из `CARRIER_ADDRESSES`, по умолчанию Mühlenweg 78, Bovenden) и адрес с другим городом отбрасываются (`isForeignToDepartment`), тогда склад ищется как фирма Abteilung в её городе с предупреждением `DEPARTMENT_ADDRESS_NOT_FOUND`. При импорте Auftrag выгрузка и загрузка (Leergut) на одном заводе остаются двумя точками; вторая помечена `samePlaceAsPrevious` и своего Termin не имеет. Auftrag с маршрутом в таблице (DSV, без Tourbemerkung-маршрута): соседние строки одного типа с той же улицей, номером дома и индексом — одна точка (`mergeSamePlaceRows`, пометка `SAME_PLACE_ROWS_MERGED`), Termin — напечатанный у любой из них, из двух разных берётся ранний (`SAME_PLACE_TERMIN_CONFLICT`); окно без длины («04:00 bis 4:00») — точное время.
- `services/*-order-import.ts` — импорт Auftrag (PDF/XLSX/изображения), `xlsx-validation.ts` — защита загрузок. Ответ модели хранится с документом (`previewJson.modelAnswer`, на страницу не отдаётся): тот же файл второй раз разбирается без ИИ (`import-reuse.ts`, `finishModelAnswer`), `POST /documents/:id/refresh` пересчитывает его по текущим правилам. PDF с текстовым слоем сверяется с ответом модели (`document-text-check.ts`): индекс, улица, номер дома и город адреса точки должны быть напечатаны в документе, иначе предупреждение `ADDRESS_NOT_IN_DOCUMENT` и поле адреса красное (адреса из выученных правил, заглушек и чужих примечаний не проверяются). Одновременно ИИ читает четыре Auftrag, остальные ждут своей очереди (`ImportSlots`, до 12 в очереди), а не получают отказ. Оборванный (`status: incomplete`) или не-JSON ответ модели сразу спрашивается второй раз (`modelAnswerOf`, `readStats.retried`, счётчик на карточке скорости); после второго — `ModelAnswerError`. Неудачный разбор отдаётся кодом 422, не 5xx: прокси Vercel/DigitalOcean подменяют 502 своей страницей, и диспетчер видел «Сервер временно недоступен» (17.11). PDF с текстом идёт в модель текстом; Termin-бланк в 1–2 страницы (mRoad Deckblatt, Fahrtenschein — `isTerminSlipText`) — страницей вместе с текстом: у распечатанной веб-формы значения в тексте отрываются от подписей. Текстовый слой из символов вместо слов (`readableShare` < 0,8, шрифт без карты символов) текстом не считается — PDF идёт страницей; если чтение по тексту не дало ни одной фирмы, адреса или города (`nothingRead`), PDF сразу перечитывается по страницам (`readStats.fromPagesAfterText`) — Deckblatt 17.11 пришёл пустым Auftrag.
- `services/route-decoding.ts` — код города в Tourbemerkung («VW SZ»): сначала по адресам строк этой фирмы в самом Auftrag, затем по кодам городов из правил адресов; иначе вопрос диспетчеру `UNKNOWN_ABBREVIATION`, ответ запоминается (`POST /address-rules/city-codes`) и Auftrag пересчитывается без ИИ.
  Точка Tourbemerkung берёт адрес из строки таблицы того же Auftrag: число перед городом («87 Wolfertschwenden») — начало индекса, опечатка в городе в 1–2 буквы прощается, если ни одна строка не печатает город как написано (`sameTownSpelling`, пометка `TOUR_REMARKS_CITY_SPELLING`); когда фирма названа иначе, а в городе одна свободная строка, берётся её адрес с пометкой `TOUR_REMARKS_COMPANY_DIFFERS`. Только без строки точка ставится по городу из Tourbemerkung.
- `services/address-resolution.ts` — адрес → координаты: выученное правило, затем геокодер; любой ответ дальше 40 км от своего города (индекс + город) отбрасывается. Индекс (из адреса или поля города) идёт в каждый запрос геокодеру, голый город без индекса не спрашивается; совпадение имени города не доказательство — при другом индексе (или без индекса в ответе) ответ меряется расстоянием (три Petershagen: 32469, 15370, 15236). Сам город для этой мерки ищется по индексу отдельно (`geocodePostcode`, Nominatim `postalcode=`): текстом «15370 Petershagen» отвечал Petershagen у Minden (17.11); текстовый ответ с другим индексом городом не считается, а если город найти нельзя — ответ без напечатанного индекса отброшен. Когда все ответы легли в тёзку, точка ставится на район напечатанного индекса (POSTCODE_CITY). Сохранение тура без координат и пересчёт маршрута ищут точку той же цепочкой, не голым текстом адреса. Адресная книга и выученные правила тоже сверяют индекс, и не по подписи, а по самой точке (владелец, 20.11: «15370 Petershagen» у Берлина стоял у Minden из сохранённого места): в полном поиске правило и место книги меряются до района напечатанного индекса (`storedFar`, 40 км), в превью без геокодера — по региону индекса из самой книги (`fitsPostcodeRegion`: первые две цифры, ≥ 3 других мест, 150 км; нет свидетелей — точку ищет полный поиск); правило с индексом другой почтовой зоны адрес точки не переписывает (`applyRulesToStop`). `known-places.ts` — место из адресной книги (та же улица с номером дома и индекс) или выученное правило того же города даёт координаты без геокодера: точка превью приходит уже с ними. `own-addresses.ts` — своя адресная книга: точные адреса сохранённых туров (фирма, улица с номером дома, индекс, точность EXACT) пишутся в `KnownAddress` с источником `OPS`; сбор из прошлых туров — только по нажатию админа (Настройки → «Адреса из Auftrag»). `edit-learning.ts` — правка точки в уже сохранённом туре (другой адрес с номером дома и индексом или точка сдвинута > 300 м) запоминается как место фирмы в её городе (`ADDRESS_RULE_LEARNED`): следующий Auftrag с этой фирмой в этом городе сразу получает исправленный адрес. `stay-places.ts` — где машины на самом деле стоят у места: после каждого BELADEN/ENTLADEN медиана стоячих точек свежего GPS в зоне точки (≥ 10 точек, ≥ 15 мин) пишется в `KnownAddress` с источником `GPS_STAY`; рабочим место становится, когда вторая стоянка в другой визит совпала в пределах 300 м (одна случайная стоянка его не меняет и не портит). Для той же двери (улица с номером и индекс, или фирма в городе) оно главнее почтовой точки: Auftrag на этот завод сразу получает координаты ворот. Когда место стало рабочим, ещё не начатые точки этой двери в турах ACTIVE/QUEUED тоже переносятся на ворота (`learned-gates.ts`, кроме точек из правила адреса), маршрут машины пересчитывается (`StopCoordinatesService.rebuildLegs`), аудит `STOP_MOVED_TO_LEARNED_GATE`, уведомление `STOP_MOVED_TO_GATE` (INFO); если маршрут не пересчитался — точки машины остаются как были. `address-check.ts` — сверка улицы, индекса и города с официальным справочником OpenPLZ (бесплатно, без ключа; при сбое — «не проверено», не тревога) и поиск фирмы без улицы рядом с её городом в TomTom Search (тот же серверный `TOMTOM_API_KEY`, лимит `TOMTOM_SEARCH_DAILY_CAP`, по умолчанию 1000 в день); найденное всё равно проходит правило 40 км. Новый адрес с улицей и номером ищется сначала в TomTom по полям (`findStructured`: улица, дом, индекс, город; тот же лимит), затем Nominatim. Любой ответ сверяется с напечатанным (`matchOf`): другая улица — отброшено; другой индекс — только в пределах 10 км от напечатанного (`SAME_POSTCODE_AREA_KM`); EXACT — только если найден сам номер дома, иначе STREET (на странице жёлтое «номер дома не найден»; только индекс/город при напечатанной улице — красное). Nominatim после 429, ошибки или таймаута отдыхает 2 мин (`geocoderPaused`), точка ищется в других источниках, а не падает. Второе мнение — другой сервис (для TomTom — Nominatim, ждём ≤ 2,5 с и только если он нашёл тот же дом); дальше 500 м — `second.status = DIFFER`, решает диспетчер. Известные места (правило, адресная книга, ворота по GPS) второй раз не спрашиваются. На странице расхождение сервисов и несогласие справочника OpenPLZ делают поле адреса красным; сохранение Auftrag блокирует только красное («под сомнением»), жёлтое — подсказка, подтвердить можно (владелец, 16.11). `stop-coordinates.ts` — админская проверка и починка точек, нарисованных не в том городе (Настройки → «Координаты точек»).
- `services/customer-notice.ts` — «Сообщить заказчику» (владелец, 18.11): при опоздании к Termin или запасе < 15 мин диспетчер открывает письмо на немецком в своей почте (адреса — профиль заказчика, `profile.notify.emails`) или копирует текст; сервер письма не отправляет, а только записывает `CUSTOMER_NOTIFIED` (кто, когда, ETA) в `OperationEvent` и аудит; Диспозиция показывает «Заказчик уведомлён HH:MM».
- `services/daily-status.ts` — статус-лист заказчика (Schnellecke в 07:00): есть у любого заказчика с линиями, автоматически — только с галочкой в профиле, иначе по кнопке. Строка принадлежит диспетчеру (`statusOwnerOf` в `customers.ts`: взял машину → он; свободная → единственный диспетчер линии или тот, у кого она основная; иначе «ничья»). Сегодня владелец считается вживую, прошлый день — по снимку в `detailsJson`. Диспетчер правит и скачивает Excel только своих машин (`?owner=mine`), весь список и чужие — админ. Точка, с которой машина уже уехала без BELADEN/ENTLADEN (открытый вопрос `STOP_DEPARTED` или свежий GPS за краем зоны), в список не идёт: строка ведёт к следующей точке, точки одного места пропускаются разом (`leftPlace`), диспетчеру — флаг `LEFT_WITHOUT_EVENT`; в туре ничего не записывается.
- `services/covers.ts` — подмена диспетчера (`DispatcherCover`): один ведёт линии и взятые машины другого до назначенного времени. Линии и машины хозяина не переписываются: «Мои», уведомления, push и владелец статуса считаются через `CoverResolver`, поэтому возврат — это конец записи (сам по времени или «Вернуть»). Оформляет сам хозяин, сам подменяющий или админ; цепочек нет. «Только выбранные линии» — свои линии и линии взятых машин (`takenLines`): диспетчер без линий отдаёт взятые машины по линиям. Экраны: кнопки на Диспозиции и страница «Команда» (`/team`). Кто что видит (владелец, 17.11): диспетчер получает уведомления (список, «прочитано», push) только по своим машинам — взятым им и свободным машинам своих линий (`vehiclesVisibleTo` → `isMine`, с учётом подмены); ничьи машины (без линии, линия без диспетчера) — только админу и общему логину, они видят всё. Карта на Диспозиции рисует те же машины, что и список (`lib/fleet-scope.ts`, `fleetOnMap`; открытая машина видна всегда): диспетчер каждый раз начинает с «Мои», «Весь парк» и «Свободные» — только посмотреть; у админа «Весь парк», кнопка «Мои машины» оставляет только взятые им самим — без свободных машин его линий (владелец, 23.11; `isMine(…, takenOnly)`) — на карте, в списке и в уведомлениях (`GET /notifications?scope=mine`) и запоминается в браузере; push на это устройство следует ей же (`PushSubscription.ownOnly`). «Понятно»: кто ведёт машину, тот закрывает уведомление для всех; «Понятно» админа по машине коллеги только убирает уведомление у самого админа (`NotificationRead`, `vehiclesOfColleagues`, `closeNotifications` в `app.ts`), у диспетчера оно остаётся; повторно поднятое уведомление (`reopen`) возвращается и админу.
- `services/dispatcher-auth.ts` — сессии, роли `admin`/`dispatcher`, CSRF; `audit-log.ts` — журнал действий. Вход держится 12 ч; галочка «Запомнить меня» — 7 дней (`REMEMBER_MS`), только личный аккаунт, общий пароль всегда 12 ч (владелец, 24.11). В токене личного аккаунта — отметка хеша пароля: новый пароль завершает старые входы в течение минуты. Браузер помнит только логин (`ops:last-login`), пароль — менеджер паролей браузера.
- `services/vehicle-ownership.ts` — чужие машины (владелец, 24.11): диспетчер меняет только свои машины (`isMine` с подменой: взятые им и свободные машины его линий) — BELADEN/ENTLADEN, Termin, туры, часы, стоп, пробки, код смены; на чужую — 403 «машина коллеги». Проверка на сервере (`preHandler` в `app.ts`), админ и общий логин меняют всё. Настройки самой машины (номер, линия, статус-лист, профиль), «Взять себе / Освободить / Передать» и предпросмотры открыты всем диспетчерам.
- `services/driver-auth.ts` — вход приложения водителя. Диспетчер выдаёт код смены на машину (`POST /vehicles/:id/driver-shift`; код показывается один раз, в базе только хеш), водитель входит номером машины и кодом (`POST /driver/auth/login`). Сессия привязана к машине и смене (`DriverShift`), не к человеку (DSGVO). `/driver/*` — отдельная дверь: сессия диспетчера её не открывает, сессия водителя не открывает ничего другого (роль `driver` в аудите). Новый код, «завершить смену» или конец смены сразу разлогинивают телефон; 5 неверных кодов подряд блокируют код (`SHIFT_CODE_ATTEMPTS`), новый выдаёт диспетчер. Сайты приложения — `DRIVER_ALLOWED_ORIGINS`.
- `routes/driver.ts` — то, что видит и делает приложение водителя (`apps/driver`, PWA для служебных Android): `GET /driver/tour` — только тур своей машины; `POST /driver/stops/:id/arrived|done|undo|problem`. Отметка водителя — настоящее событие (владелец, 17.11): `Event.source = DRIVER`, аудит с ролью `driver`, диспетчеру — уведомление `DRIVER_ARRIVAL` / `DRIVER_STOP_EVENT` со сверкой по Webfleet (`driverGpsCheck`: в зоне точки / в N км — «проверьте» / GPS устарел / позиции нет); отметка записывается при любом ответе Webfleet, позиция телефона не используется. BELADEN/ENTLADEN без «Прибыл» — только для точки того же места после выполненной предыдущей (Leergut). Водитель отменяет свою отметку 5 минут (`DRIVER_UNDO_MS`), потом — диспетчер тем же «Отменить» (`revertAutoStopEvent` понимает и `STOP_EVENT_DRIVER`); история остаётся, пишется `…_REVERTED`. «Проблема на точке» — уведомление `DRIVER_PROBLEM` (решение, срочное). Без сети приложение открывается из кэша (`apps/driver/public/sw.js`) с последним туром, «Прибыл»/«выполнено» сохраняются на телефоне со временем нажатия по часам сервера (`apps/driver/src/offline.ts`) и уходят по порядку при связи: сервер берёт `at` (не старше 12 ч — `OFFLINE_MARK_MAX_MS`, не в будущем), GPS сверяет на это время, уведомление с «(без сети, получено в HH:MM)», 5 минут на отмену считаются от получения. Код смены выдаёт диспетчер в карточке машины, вкладка «Тур» (`apps/web/src/components/DriverShiftCode.tsx`). Вкладки приложения (владелец, 19.11): «Документы» — только данные Auftrag из тура (номер, прицеп, Tourbemerkung, Ref, LDM, указания), файл Auftrag водителю не показывается (цены, данные заказчика); «Диспетчер» — звонок тому, кто ведёт машину (`dispatcherOf` в `routes/driver.ts`: взял машину → он, подмена → подменяющий, свободная → диспетчер линии по `coveredStatusOwner`), только имя и `Dispatcher.workPhone` — служебный номер, его вносит сам диспетчер (меню → «Телефон для водителей») или админ на странице диспетчеров.

## Жёсткие правила

1. **Секреты** — только в серверном окружении. Никогда в `VITE_*`, git, логах, ответах API или чате. Ошибки внешних API не пересказывают их сырой текст пользователю.
2. **Webfleet — только чтение.** Не отправлять в Webfleet заказы, сообщения, команды. Лимит `showObjectReportExtern` — 6/мин, приложение делает 1/мин. При ошибке входа — пауза 30 мин (защита от блокировки пользователя).
3. **Автоматика только по реальному GPS.** Прибытие может ставиться само только по свежему GPS Webfleet: точка — это зона, а не адрес: 1 км вокруг него (`DEFAULT_ARRIVAL_RADIUS_METERS`), если диспетчер не выбрал свой радиус (`Stop.arrivalRadiusMeters`); когда следующая точка в том же городе, зона кончается на полпути к ней (`zoneRadiusOf`). В ядре зоны (до 500 м от адреса, `ENTRY_CORE_METERS`) прибытие — стоянка ≥ 3 мин или два замера подряд не быстрее 15 км/ч (въехала и ползёт в очереди у ворот; проезд мимо на скорости не считается), время = въезд в зону. Дальше 500 м в зоне лежат дороги вокруг завода: там считается только стоянка ≥ 3 мин (не пока машина ещё в зоне только что выполненной точки), время = когда встала. Уведомление `AUTO_ARRIVAL` с отменой, аудит с ролью `system`. Расчётная позиция никогда не ставит фактические события. Всё это — только около планового времени точки (`stop-window.ts`): стоянка, закончившаяся раньше чем за 12 ч до Termin/плана, и стоянка до последнего BELADEN/ENTLADEN другого тура машины — чужой рейс, по ней ничего не ставится; отмена автоотметки смотрит только на этот тур и снимает такое автоприбытие. BELADEN/ENTLADEN ставит диспетчер или водитель в своём приложении (владелец, 17.11: отметка водителя записывается сразу, диспетчер получает уведомление со сверкой по Webfleet и может отменить — см. `routes/driver.ts`); сам он записывается, только если по свежему GPS машина простояла в зоне точки ≥ 20 мин (скачок GPS из зоны на 1–2 мин стоянку не обрывает; считается и стоянка до позднего ручного прибытия) и затем отъехала на 10 км (вышла из города) — или, если следующая точка в том же городе (дальше 300 м), приехала в её зону: время = выезд из зоны, уведомление `AUTO_STOP_EVENT` с «Отменить», аудит с ролью `system`. Выгрузка и загрузка в одном месте (точки ≤ 300 м, обычно ENTLADEN + BELADEN Leergut) — одна стоянка: признаки отъезда считаются от первой точки после них, обе отметки пишутся разом на время выезда (`chainStopIds`, вторая получает прибытие вместе с событием), уведомление одно, «Отменить» снимает обе. После короткой стоянки или через 30 мин без признаков — только вопрос `STOP_DEPARTED` (для точек одного места — один на все, ответ записывает все). Машину, которую никто не взял («Свободна», нет `assignedDispatcherId`), спросить некого (владелец, 16.11): вопроса нет; после стоянки ≥ 20 мин и 30 мин вне зоны без возврата отметка пишется сама на время выезда (`awayMinutes`, «Отменить»), после короткой стоянки точка просто остаётся открытой. Стоянка не у адреса (владелец, 18.11, Tesla): машина в зону точки не въезжала, но стояла ≥ 20 мин в пределах 5 км от адреса (`OFFSITE_MAX_METERS`) и потом уехала дальше (10 км от стоянки или в зону следующей точки того же города) — прибытие пишется на начало стоянки, BELADEN/ENTLADEN на её конец (точки одного места разом), одно уведомление `AUTO_STOP_EVENT` с `offsite` и «Отменить» (снимает и прибытие, и урок места, `forgetVisitOf`); из нескольких стоянок берётся совпавшая с воротами `GPS_STAY`, иначе самая длинная (`pickOffsiteStay`); стоянка учит ворота этой двери (`learnOffsiteVisit`, правило двух визитов то же). Отклонение от маршрута (два замера свежего GPS дальше 2 км от линии): маршрут до следующей точки перестраивается сам от позиции машины (`TrafficOperationsService.rerouteFromGps`, не чаще раза в 10 мин на этап), событие и аудит `ROUTE_REBUILT_AUTO` с ролью `system`, уведомление `ROUTE_DEVIATION` с `rebuilt` — только для сведения; если перестроить не удалось, диспетчера просят посмотреть варианты.
4. **Источник позиции всегда виден**: свежий Webfleet / устаревший Webfleet / расчёт. Устаревшие данные не выдаются за актуальные.
5. **Production-база**: никаких ручных миграций, импортов и изменений данных без backup и явного «да» владельца. `db:reset` — только локально.
   Деплой автоматический: слияние в `main` = выкладка (API на DigitalOcean с PRE_DEPLOY-миграцией, web на Vercel). Новые миграции схемы — отдельным PR с явной пометкой в описании.
6. **История неизменяема**: завершённые точки и события не удаляются; редактируется только будущий тур с проверкой версии.
7. Мутирующие маршруты: Zod-валидация, проверка роли (`requireDispatcherRoles('admin')` для настроек), запись в `writeAuditLog`.
8. Персональные данные водителей (DSGVO): не хранить больше, чем нужно; телеметрия привязана к машине, а не к водителю. GPS в базе хранится `TELEMETRY_RETENTION_DAYS` дней (по умолчанию 5), старое удаляется само (`services/telemetry-retention.ts`).
