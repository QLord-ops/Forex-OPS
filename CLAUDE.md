# OPS Disponent — инструкции для Claude Code

Диспетчерская система грузового автопарка Forex GmbH (Bovenden). Пользователь — диспетчер: управляет машинами, турами, Auftrag, BELADEN/ENTLADEN, ETA и пробками. Интерфейс и тексты для пользователя — **на русском**; немецкие отраслевые термины (Auftrag, Tourbemerkung, BELADEN, ENTLADEN, LDM, Termin) остаются как есть.

## Стек

- `apps/api` — Fastify 5, Prisma 6, Zod, TypeScript (ESM, NodeNext). Production: PostgreSQL (DigitalOcean `ops-disponent-prod`), локально и в тестах — SQLite (`prisma/sqlite/`).
- `apps/web` — React 18, Vite, Tailwind, MapLibre (ленивая загрузка), lucide-react.
- Тесты: Vitest (`apps/*/tests`), Playwright (`e2e/`). Node 22 (`.nvmrc`).

## Команды

```bash
npm install
npm run db:setup          # локальная SQLite + seed
npm run dev               # API :3001, web :5173
npm run lint && npm run typecheck && npm test && npm run build
npm run test:e2e
npm run webfleet:check -w @ops/api   # одна read-only проверка ключа Webfleet
```

Перед каждым коммитом — все четыре проверки зелёные. Новая логика сопровождается тестом в `apps/api/tests`.

## Где что лежит

- `apps/api/src/app.ts` — все маршруты; сервисы — `apps/api/src/services/*`.
- `services/webfleet.ts` — Webfleet: синхронизация, сопоставление машин, ошибки, привязки.
- `services/vehicle-clock.ts` — расчёт часов машины (ЕС 561/2006), `termin-planner.ts` — паузы в пути по тахографу Webfleet (общий движок ETA и Termin: отдых 11 ч, 9 ч при раннем Termin), `tours.ts` — туры, `operations.ts` — прибытие/стоянки, `termin-groups.ts` — общий Termin: выгрузка и загрузка в одном месте (соседние точки ≤ 300 м, та же фирма или улица + индекс) идут под одним Termin, он хранится на первой точке места. Склад Abteilung («vorladen», «Lager», «divers») берёт только адрес, напечатанный в самом блоке Abteilung: адрес перевозчика (`carrierAddress` от модели и своя база из `CARRIER_ADDRESSES`, по умолчанию Mühlenweg 78, Bovenden) и адрес с другим городом отбрасываются (`isForeignToDepartment`), тогда склад ищется как фирма Abteilung в её городе с предупреждением `DEPARTMENT_ADDRESS_NOT_FOUND`. При импорте Auftrag выгрузка и загрузка (Leergut) на одном заводе остаются двумя точками; вторая помечена `samePlaceAsPrevious` и своего Termin не имеет.
- `services/*-order-import.ts` — импорт Auftrag (PDF/XLSX/изображения), `xlsx-validation.ts` — защита загрузок. Ответ модели хранится с документом (`previewJson.modelAnswer`, на страницу не отдаётся): тот же файл второй раз разбирается без ИИ (`import-reuse.ts`, `finishModelAnswer`), `POST /documents/:id/refresh` пересчитывает его по текущим правилам. PDF с текстом идёт в модель текстом; Termin-бланк в 1–2 страницы (mRoad Deckblatt, Fahrtenschein — `isTerminSlipText`) — страницей вместе с текстом: у распечатанной веб-формы значения в тексте отрываются от подписей.
- `services/route-decoding.ts` — код города в Tourbemerkung («VW SZ»): сначала по адресам строк этой фирмы в самом Auftrag, затем по кодам городов из правил адресов; иначе вопрос диспетчеру `UNKNOWN_ABBREVIATION`, ответ запоминается (`POST /address-rules/city-codes`) и Auftrag пересчитывается без ИИ.
  Точка Tourbemerkung берёт адрес из строки таблицы того же Auftrag: число перед городом («87 Wolfertschwenden») — начало индекса, опечатка в городе в 1–2 буквы прощается, если ни одна строка не печатает город как написано (`sameTownSpelling`, пометка `TOUR_REMARKS_CITY_SPELLING`); когда фирма названа иначе, а в городе одна свободная строка, берётся её адрес с пометкой `TOUR_REMARKS_COMPANY_DIFFERS`. Только без строки точка ставится по городу из Tourbemerkung.
- `services/address-resolution.ts` — адрес → координаты: выученное правило, затем геокодер; любой ответ дальше 40 км от своего города (индекс + город) отбрасывается. `known-places.ts` — место из адресной книги (та же улица с номером дома и индекс) или выученное правило того же города даёт координаты без геокодера: точка превью приходит уже с ними. `own-addresses.ts` — своя адресная книга: точные адреса сохранённых туров (фирма, улица с номером дома, индекс, точность EXACT) пишутся в `KnownAddress` с источником `OPS`; сбор из прошлых туров — только по нажатию админа (Настройки → «Адреса из Auftrag»). `address-check.ts` — сверка улицы, индекса и города с официальным справочником OpenPLZ (бесплатно, без ключа; при сбое — «не проверено», не тревога) и поиск фирмы без улицы рядом с её городом в TomTom Search (тот же серверный `TOMTOM_API_KEY`, лимит `TOMTOM_SEARCH_DAILY_CAP`, по умолчанию 1000 в день); найденное всё равно проходит правило 40 км. `stop-coordinates.ts` — админская проверка и починка точек, нарисованных не в том городе (Настройки → «Координаты точек»).
- `services/daily-status.ts` — статус-лист заказчика (Schnellecke в 07:00): есть у любого заказчика с линиями, автоматически — только с галочкой в профиле, иначе по кнопке. Строка принадлежит диспетчеру (`statusOwnerOf` в `customers.ts`: взял машину → он; свободная → единственный диспетчер линии или тот, у кого она основная; иначе «ничья»). Сегодня владелец считается вживую, прошлый день — по снимку в `detailsJson`. Диспетчер правит и скачивает Excel только своих машин (`?owner=mine`), весь список и чужие — админ.
- `services/covers.ts` — подмена диспетчера (`DispatcherCover`): один ведёт линии и взятые машины другого до назначенного времени. Линии и машины хозяина не переписываются: «Мои», уведомления, push и владелец статуса считаются через `CoverResolver`, поэтому возврат — это конец записи (сам по времени или «Вернуть»). Оформляет сам хозяин, сам подменяющий или админ; цепочек нет. «Только выбранные линии» — свои линии и линии взятых машин (`takenLines`): диспетчер без линий отдаёт взятые машины по линиям. Экраны: кнопки на Диспозиции и страница «Команда» (`/team`).
- `services/dispatcher-auth.ts` — сессии, роли `admin`/`dispatcher`, CSRF; `audit-log.ts` — журнал действий.
- Документация: `docs/REMAINING_WORK.md` (что осталось), `docs/webfleet-integration.md`, `docs/DEPLOYMENT.md`, `DESIGN.md`.

## Жёсткие правила

1. **Секреты** — только в серверном окружении. Никогда в `VITE_*`, git, логах, ответах API или чате. Ошибки внешних API не пересказывают их сырой текст пользователю.
2. **Webfleet — только чтение.** Не отправлять в Webfleet заказы, сообщения, команды. Лимит `showObjectReportExtern` — 6/мин, приложение делает 1/мин. При ошибке входа — пауза 30 мин (защита от блокировки пользователя).
3. **Автоматика только по реальному GPS.** Прибытие может ставиться само только по свежему GPS Webfleet: машина в зоне точки (по умолчанию 500 м, `Stop.arrivalRadiusMeters`) и стоит ≥ 3 мин; время = въезд в зону. У точки без выбранного вручную радиуса прибытием считается и стоянка ≥ 5 мин в кольце 1 км (не пока машина ещё в зоне только что выполненной точки); время = когда встала, радиус точки становится 1 км. Уведомление `AUTO_ARRIVAL` с отменой, аудит с ролью `system`. Расчётная позиция никогда не ставит фактические события. BELADEN/ENTLADEN ставит диспетчер; сам он записывается, только если по свежему GPS машина простояла в зоне точки ≥ 20 мин (скачок GPS из зоны на 1–2 мин стоянку не обрывает; считается и стоянка до позднего ручного прибытия) и затем отъехала на 10 км (вышла из города) — или, если следующая точка в том же городе (дальше 300 м), приехала в её зону: время = выезд из зоны, уведомление `AUTO_STOP_EVENT` с «Отменить», аудит с ролью `system`. После короткой стоянки, у точек в одном месте или через 30 мин без признаков — только вопрос `STOP_DEPARTED`. Отклонение от маршрута (два замера свежего GPS дальше 2 км от линии): маршрут до следующей точки перестраивается сам от позиции машины (`TrafficOperationsService.rerouteFromGps`, не чаще раза в 10 мин на этап), событие и аудит `ROUTE_REBUILT_AUTO` с ролью `system`, уведомление `ROUTE_DEVIATION` с `rebuilt` — только для сведения; если перестроить не удалось, диспетчера просят посмотреть варианты.
4. **Источник позиции всегда виден**: свежий Webfleet / устаревший Webfleet / расчёт. Устаревшие данные не выдаются за актуальные.
5. **Production-база**: никаких ручных миграций, импортов и изменений данных без backup и явного «да» владельца. `db:reset` — только локально.
   Деплой автоматический: слияние в `main` = выкладка (API на DigitalOcean с PRE_DEPLOY-миграцией, web на Vercel). Новые миграции схемы — отдельным PR с явной пометкой в описании.
6. **История неизменяема**: завершённые точки и события не удаляются; редактируется только будущий тур с проверкой версии.
7. Мутирующие маршруты: Zod-валидация, проверка роли (`requireDispatcherRoles('admin')` для настроек), запись в `writeAuditLog`.
8. Персональные данные водителей (DSGVO): не хранить больше, чем нужно; телеметрия привязана к машине, а не к водителю. GPS в базе хранится `TELEMETRY_RETENTION_DAYS` дней (по умолчанию 5), старое удаляется само (`services/telemetry-retention.ts`).

## Стиль

- Коммиты: Conventional Commits (`feat(webfleet): …`, `fix(import): …`), работа в ветке, не прямо в `main`.
