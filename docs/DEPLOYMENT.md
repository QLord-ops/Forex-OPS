# Развёртывание OPS Disponent

## Целевая схема

- `apps/web` — статический Vite-фронтенд на Vercel.
- `apps/api` — отдельный постоянно работающий Node.js/Fastify-сервис из `apps/api/Dockerfile` на DigitalOcean App Platform (`.do/app.yaml`, пошагово — в `docs/REMAINING_WORK.md`).
- База — PostgreSQL `ops-disponent-prod` в DigitalOcean. Neon остаётся запасным вариантом; `DATABASE_URL_UNPOOLED` нужен только при pooled-подключении.

Fastify не следует считать обычной статической частью Vercel-фронтенда: API держит SSE-соединения, выполняет периодические проверки уведомлений и синхронизацию Webfleet. Отдельный сервис даёт предсказуемый жизненный цикл процесса. Vercel-конфигурация API пока сохранена для обратной совместимости, но не является рекомендуемой production-схемой.

## Переменные окружения

Список ключей без значений находится в `apps/api/.env.example`. В production-хостинге задаются как минимум:

- `DATABASE_URL` — pooled Neon URL для обычных запросов;
- `DATABASE_URL_UNPOOLED` — direct Neon URL для Prisma Migrate и импорта;
- `API_HOST=0.0.0.0`;
- `ALLOWED_ORIGINS` — точные HTTPS-домены фронтенда через запятую;
- хэши паролей, `SESSION_SECRET` и ключи внешних провайдеров — только в секретах хостинга;
- `TRUST_PROXY_HOPS` — сколько прокси стоит перед API (по умолчанию в production 2: Vercel → DigitalOcean). По нему API видит настоящий адрес пользователя для лимита неудачных входов.

## Разбор Auftrag

Цель — до 10 секунд на Auftrag. PDF с текстовым слоем (все сгенерированные Auftrag) читается на сервере (`services/pdf-text.ts`, pdf.js) и уходит ИИ текстом, постранично; скан без текста уходит страницами-картинками, это медленнее. ИИ возвращает только данные документа без оценок по полям — уверенность считает сервер (`field-confidence.ts`). Время чтения видно в журнале (`aiMs`, `readMode`) и в проверке Auftrag («распознан за N с»).

Страховка от долгого ответа: чтение может занимать минуты, а прокси Vercel перед API ждёт не дольше 120 с. Поэтому загрузка (`POST /imports/pdf/preview`, `/imports/image/preview`, `POST /documents/:id/reparse`) через 20 с отвечает `202 { jobId }`, разбор продолжается на сервере, а страница каждые 2 с спрашивает `GET /imports/jobs/:id` (202 — ещё идёт, 200 — готово, иначе — ошибка со своим текстом). Задача живёт в памяти одного экземпляра API 15 минут и доступна только сессии, которая её начала. Время ответа ИИ пишется в журнал как `aiMs`.

## Хранение GPS

Позиции Webfleet сохраняются каждую минуту по каждой машине. Хранится только последние `TELEMETRY_RETENTION_DAYS` дней (по умолчанию 5).

- Очистка идёт каждый час, по каждой машине пачками по 2 000 строк с паузами.
- За один проход удаляется не больше 500 000 строк, остальное — через 5 минут. Так первая большая очистка не нагружает базу разом.
- Последняя позиция каждой машины остаётся всегда.
- В журнал аудита пишется `TELEMETRY_PURGED` с числом удалённых строк, роль `system`.

Самому OPS нужны данные максимум за последние 12 часов: прибытие, выезд, прошлый тур. Трек за день берётся у Webfleet, полная история поездок тоже хранится там. Туры, BELADEN/ENTLADEN и уведомления очистка не трогает.

`GET /health` проверяет и базу: при недоступной базе отвечает 503 без подробностей. Seed (`db:seed`) удаляет машины и туры и отказывается работать в production и с нелокальной базой (для отдельной тестовой базы: `OPS_SEED_ALLOW_REMOTE=yes`).

Фронтенду передаётся `VITE_API_BASE_URL` с публичным HTTPS-адресом API. Серверные ключи нельзя помещать в `VITE_*`.

## Push-уведомления на телефоны (PWA)

Push работает, когда в окружении API заданы VAPID-ключи. Без них переключатель «Push на этот телефон» показывает «не настроен на сервере», остальное приложение работает как обычно.

1. Один раз сгенерируйте пару ключей у себя в терминале: `npm run push:keys -w @ops/api`.
2. Перенесите три строки в переменные окружения приложения на DigitalOcean: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (как секрет) и `VAPID_SUBJECT` (`mailto:` адрес диспетчерской).
3. После перезапуска диспетчер включает «Push на этот телефон» в «Ещё» или в «Настройках». На iPhone это возможно только в приложении, добавленном на экран «Домой» (iOS 16.4+).

Закрытый личный ключ не попадает ни в git, ни в веб-сборку, ни в чат. Если ключи сменить, телефоны нужно подписать заново.

Что приходит: в рабочие часы телефона — все открытые решения, вне рабочих часов — только срочные (машина уехала без BELADEN/ENTLADEN, критическая стоянка). На телефоне одно уведомление на машину. Подписка удаляется при выходе, при выключении push и когда push-сервис отвечает, что подписки больше нет.

## Подготовленный переход SQLite → Neon

Эти команды нельзя запускать против рабочей базы без отдельного подтверждения и резервной копии.

1. Создать отдельную Neon branch для проверки миграции.
2. Указать pooled `DATABASE_URL` и direct `DATABASE_URL_UNPOOLED` этой ветки.
3. Применить версионированную схему: `npm run db:deploy --workspace @ops/api`.
4. Выполнить только проверку источника, связей и количества строк: `npm run db:import-sqlite --workspace @ops/api`.
5. Проверить отчёт dry-run. Импорт разрешён только в полностью пустую целевую базу.
6. После явного подтверждения выполнить `npm run db:import-sqlite --workspace @ops/api -- --apply`.
7. Сверить количества строк и выполнить `npm run db:check --workspace @ops/api`.
8. Провести smoke-тест на Neon branch и только затем планировать переключение production URL.

Скрипт переносит все текущие модели, проверяет ключевые связи до записи, выполняет запись транзакционно и после неё сравнивает количество строк. Оригинальная SQLite-база не изменяется.

## Запуск контейнера API

Сборка выполняется из корня репозитория:

```bash
docker build -f apps/api/Dockerfile -t ops-disponent-api .
```

Миграции выполняются отдельной release/pre-deploy командой, а не параллельно каждым экземпляром API:

```bash
npm run db:deploy --workspace @ops/api
```

После успешной миграции контейнер запускается командой из Dockerfile. Хостинг должен проверять `GET /health` и корректно передавать `SIGTERM` при остановке.

## Утренний статус-лист (07:00)

- Статус-лист линии Schnellecke сервер формирует сам в 07:00 по Берлину (тик раз в 15 с, `DailyStatusService.runIfDue`). Нужен постоянно работающий процесс API — это DigitalOcean, не Vercel.
- Данные водителей из Webfleet хранятся только в памяти и после перезапуска набираются около 5 минут. Поэтому **не сливать в `main` с 06:45 до 07:15**: если сервер перезапустится в это время, список подождёт Webfleet до 10 минут и выйдет с пометкой «предварительно».
- Если в 07:00 сервер был недоступен, список сформируется при первом открытии страницы «Статус» за сегодня или по кнопке «Сформировать заново».
