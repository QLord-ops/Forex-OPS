Этот файл фиксирует состояние после аудита безопасности. Код фаз 0–7 готов и закоммичен, но production ещё не обновлён.

## Перед следующим production-деплоем

1. В DigitalOcean проверить, что для базы `Forex-ops-yev` создан свежий backup или доступна точка восстановления.
2. Временно добавить текущий IP разработчика в Trusted Sources базы. Не открывать базу для `0.0.0.0/0`.
3. Выполнить только чтение и проверку подключения к PostgreSQL, статуса Prisma migrations и контрольных количеств записей.
4. Выбрать права текущего входа:
   - для одного владельца задать `ADMIN_PASSWORD_HASH` тем же хэшем, что и `DISPATCHER_PASSWORD_HASH`;
   - для нескольких сотрудников использовать отдельные пароли администратора и диспетчера.
5. В окружении production API задать `ALLOWED_ORIGINS` точными HTTPS-адресами интерфейса и проверить наличие `SESSION_SECRET`, обоих хэшей паролей, `DATABASE_URL` и `DATABASE_URL_UNPOOLED`.
6. Применить Prisma migrations к рабочей базе только после backup, затем сверить машины, туры, точки, события и журнал аудита.
7. Развернуть API и web, после чего проверить вход, роли, CORS, security headers, импорт Auftrag, назначение машины, ETA, прибытие, BELADEN/ENTLADEN, изменение будущего тура и SSE-уведомления.

Новая база Neon для этого не обязательна: существующая `Forex-ops-yev` является PostgreSQL в DigitalOcean и подходит для приложения.
