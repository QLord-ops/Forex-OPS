# Подключение Webfleet к OPS Disponent

Актуализировано: 2026-10-27.

## Что уже подготовлено

Интеграция реализована как односторонний read-only источник телеметрии. OPS Disponent не отправляет в Webfleet заказы, команды, сообщения водителю и изменения машин.

- Снимок всех доступных машин запрашивается не чаще одного раза в 60 секунд через `showObjectReportExtern`.
- Координаты, время позиции, зажигание и признак стоянки сохраняются отдельно от расчётной позиции.
- Точная привязка выполняется по номеру объекта или нормализованному госномеру. Неоднозначные машины не привязываются автоматически.
- Фактическая позиция используется как старт для нового расчёта маршрута, ETA-сценария, перепланирования и обновления трафика.
- **Автоприбытие:** если свежая позиция внутри зоны следующей точки (по умолчанию 500 м, у точки можно выбрать 300 м – 2 км) и машина стоит по признаку `standstill` не меньше 3 минут, прибытие ставится автоматически со временем въезда в зону. Приходит уведомление «прибыла (автоматически по GPS)» с кнопкой «Отменить прибытие». После отмены повторное автоприбытие возможно только после выезда из зоны и возвращения. Отключается переменной `AUTO_ARRIVAL_ENABLED=false` — тогда остаётся подсказка «машина стоит на точке, подтвердите прибытие».
- При сбое остаются последние данные с их возрастом; приложение не выдаёт их за актуальные.
- Расчётные часы машины OPS не заменяются данными тахографа Webfleet.

## Что нужно получить у Webfleet

1. API key для WEBFLEET.connect. Его выдача запрашивается через аккаунт Webfleet и может зависеть от договора.
2. Имя аккаунта Webfleet.
3. Отдельного технического пользователя с правом `Access to interface WEBFLEET.connect`.
4. Этому пользователю дать доступ только к нужной группе машин и только права чтения.

Официальные инструкции:

## Настройка сервера

Секреты задаются только в переменных окружения API-проекта. Их нельзя вводить в браузере, сохранять в Git или отправлять в чат.

```dotenv
WEBFLEET_ACCOUNT="..."
WEBFLEET_API_KEY="..."
WEBFLEET_USERNAME="..."
WEBFLEET_PASSWORD="..."
WEBFLEET_BASE_URL="https://csv.webfleet.com/extern"
```

Перед перезапуском API ключ можно проверить одной командой. Она делает один запрос только на чтение, ничего не пишет в базу и не печатает ключи:

```bash
npm run webfleet:check -w @ops/api
```

Скрипт покажет число машин с актуальной позицией и для каждой — найдена ли она в OPS. Если вход отклонён, не повторяйте проверку много раз подряд: Webfleet может заблокировать пользователя.

После настройки нужно перезапустить или заново развернуть API. На странице «Грузовики» блок Webfleet покажет результат первой синхронизации и список объектов, которые не удалось однозначно сопоставить.

### Ошибки подключения

Блок Webfleet показывает причину сбоя и код Webfleet (если он есть), но никогда не показывает сырой ответ провайдера:

| Причина | Что делать | Следующая автоматическая попытка |
| --- | --- | --- |
| Вход отклонён | Проверить аккаунт, пользователя, пароль и API key | через 30 минут |
| Нет прав | Дать пользователю право WEBFLEET.connect и доступ к группе машин | через 30 минут |
| Лимит запросов | Ничего, подождать | через 5 минут |
| Сеть / неожиданный ответ | Проверить доступность csv.webfleet.com | через 5 минут |

### Ручная привязка машин

Если номер объекта в Webfleet отличается от номера машины в OPS (например, «LKW 125» и «125»), администратор привязывает объект вручную: «Грузовики» → Webfleet → «Требуют сопоставления» → выбрать грузовик → «Привязать». Привязка сохраняется и записывается в журнал аудита. Отвязка не удаляет историю позиций. Один объект Webfleet можно привязать только к одной машине, и наоборот.

### Подсказки привязки

Под «Грузовики» → Webfleet сервер предлагает пары «объект Webfleet → машина OPS»: сначала по совпадающему госномеру («B CY 3786» ↔ «B-CY3786»), затем по цифрам номера («B CY 2868» ↔ «2868»), если пара однозначна с обеих сторон. Прицепы не предлагаются. Ничего не привязывается автоматически: каждую пару подтверждает администратор.

## Карточка машины

Кнопка «i» в строке машины, двойной клик по строке или клик по машине на карте открывает карточку справа на главной. Весь парк виден на карте: стрелка по курсу у едущих машин, точка у стоящих; цвет показывает источник — свежий GPS, устаревший GPS или расчёт.

Источники данных (только чтение):

| Отчёт | Как часто | Что даёт |
|---|---|---|
| `showObjectReportExtern` (лимит 6/мин) | раз в минуту, тот же снимок, что и раньше | позиция, скорость (км/ч), курс, адрес, топливо (‰), пробег, моточасы, зажигание, водитель и его состояние |
| `getRemainingDrivingTimesEU` (лимит 10/мин) | раз в 5 минут | тахограф: остаток вождения за день и неделю, начало и самый поздний конец смены, перерыв, отдых, удлинённые дни и сокращённые отдыхи, нарушения |
| `showVehicleReportExtern` (лимит 10/мин) | раз в час | госномер, VIN, объём бака |

Дополнительные отчёты запрашиваются только после успешного основного снимка, поэтому неверный пароль даёт одну неудачную попытку входа, а не три.

Защита данных: имя водителя, его состояние и время вождения хранятся только в памяти сервера и не пишутся в базу, историю или логи. После перезапуска они появляются в течение 5 минут. В историю телеметрии записываются только данные машины: скорость, курс, адрес, топливо, пробег, моточасы. Время вождения из Webfleet — ориентировочное и показывается отдельно от расчётных часов машины OPS.

## Безопасный ввод в эксплуатацию

1. Создать в Webfleet тестовую группу из 2–3 машин и дать техническому пользователю доступ только к ней.
2. Проверить точное совпадение номера машины или госномера с карточкой OPS.
3. Сутки сравнивать положение и время обновления в двух системах.
4. Проверить построение чернового маршрута от выбранной машины и уведомление о предполагаемом прибытии.
5. После проверки постепенно расширять группу доступных машин.

Новая машина из Webfleet намеренно не создаётся автоматически. Это защищает от дублей и неверной привязки. Несопоставленные и неоднозначные объекты видны в блоке подключения.

## Ограничения первой версии

- `showObjectReportExtern` разрешает до шести запросов в минуту; приложение делает один общий снимок не чаще раза в минуту.
- В API время позиции и статус могут быть неактуальными. Позиции старше 2 минут помечаются устаревшими, старше 30 минут не используются для расчёта.
- Скорость берётся в км/ч по справочнику WEBFLEET.connect; для определения стоянки по-прежнему сначала применяется официальный признак `standstill`.
- AdBlue, поездки и история стоянок пока не подключены.
- Публичной фиксированной цены API нет; стоимость и включённые функции нужно подтвердить у менеджера Webfleet по действующему договору.

## Следующие этапы

1. Пилот фактических GPS-позиций и контроль сопоставления.
2. Отдельный журнал качества данных: возраст позиции, пропуски и смена привязки.
3. После подтверждения доступных отчётов — история поездок/стоянок, пробег, топливо и AdBlue.
4. При наличии тахографического продукта — отдельный read-only виджет фактических часов водителя с явной пометкой, что это не расчётные часы машины.
5. Только после отдельного решения — изучение двусторонних команд. Текущая интеграция остаётся read-only.
